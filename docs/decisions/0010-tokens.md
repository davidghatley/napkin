# 0010: Token sources and preview modes

Status: proposed · 2026-10-21 · AI tokens builder, implementing David's TOK-01..05 scope.

`napkin.json` locates a JSON token source or CSS custom properties relative to the config file. JSON follows the secret-sauce shape: grouped `tokens` arrays, scalar or mode-keyed `value`, `color.themes`, and `type.families` / `type.groups[].styles`. Typography properties are exposed as `<style>-<kebab-property>` variables; family names as `font-<family>`. The fixture values and descriptions were written for napkin; the other project was read only.

Source ranges preserve bytes: JSON literal ranges from the existing Babel parser and CSS declaration ranges are replaced directly. A scalar value is shared across modes; a mode-keyed object edits only that mode. No-op writes preserve the source and generated CSS byte for byte. Content hashes are revisions; changed on-disk bytes reject a stale write. Parent-directory watching survives atomic replacement; broken files report the problem while keeping the last valid preview.

`commit.writeTokens` is the token writer. Source and owned generated CSS each use fsync and atomic rename. The source is authoritative if a process stops between the two replacements. Token edits name the authenticated caller in token history and workspace activity. Token undo is not part of this lane. Writes cannot follow configured paths or symlinks outside the project containing napkin.json.

A CSS header beginning `/* generated by napkin` opts into regeneration of existing matching declarations. Other generated / do-not-edit headers are external: edit the source, leave CSS untouched, and display “run your token build to update tokens.css”. An unmarked CSS file can also have matching declarations updated. A mode with no explicit CSS declaration must first be added in the source. napkin does not run external build commands.

Preview variables are scoped to component mounts, not editor chrome. A mode change updates one CSS rule and never edits or rebuilds components. Token edits update only changed declarations; duplicate SSE/HTTP responses do not repaint twice. The panel uses its existing scoped, batched commit callback for binding and snapping. Consumer apps import ordinary generated CSS; components retain only `var(--name)` values.

Nearest colours use Cartesian OKLab distance (alpha differences also flag an off-token literal); lengths use absolute pixel difference, with rem/em treated as 16 px for the pure helper. Unsupported expressions/keywords are not assigned a numerical distance. These limits are explicit rather than silently converting expressions.

Performance note: the default benchmark fits all 200 frames into one viewport, with every cell explicitly mounted and every computed colour verified. Optional `node bench/tokens.js --viewport` exercises the normal 100% canvas viewport and records its visible frame count in separate `*-viewport.txt` evidence. Token refresh has its own event, so it does not rebuild the layers tree; with no selection it does not force an unnecessary overlay layout read.
